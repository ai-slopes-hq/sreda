# Plan 16 — the new visual style Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** The app takes the redesigned look of spec §1b in all six skins — tokens, faces, radii and shadows, panels,
floating windows, chrome, sidebar, frames and the META-SEQ drawer — plus the small decided behaviours (frame tools on
hover, the sidebar narrows the canvas, no SAVE AS / NEW in LIBRARY, no column for a side without ports).

**Architecture:** Colours stay tokens in `packages/ui/src/skins.ts` (three new ones per skin); everything else that
§1b scales (radii, shadows, ring, faces, jack and frame-head sizes) becomes CSS custom properties in a second `:root`
block of `canvas.css`, built from the colour tokens so it follows the skin. Components keep their structure and class
names; markup changes only where §1b adds an element (icons, segmented controls, pills, footers). Geometry that the
document depends on (`GHEAD`, the jack centre, module sizes) changes in `packages/core` and the Rust specs.

**Tech Stack:** SolidJS + TypeScript (Vitest, @solidjs/testing-library), Electron (Playwright e2e), Rust specs
exported to `specs.json`, `@fontsource/ibm-plex-mono` and `@fontsource/ibm-plex-sans`.

**Spec:** `docs/superpowers/specs/2026-10-07-canvas-ux-design.md` §1b (revision 35) and the amended §1a, §2, §5,
§5a, §6; boards `docs/prototype/Redesign*.dc.html` (render one with `node docs/prototype/check/render.js <board>
<out>.html`; where a board and §1b disagree, §1b wins).

## Global Constraints

- Every colour comes from a skin token; `skins.test.ts` forbids colour literals outside `skins.ts` and the first
  `:root` block of `canvas.css` (shadows and rings are built with `color-mix(… var(--token) …)`).
- Mono (`'IBM Plex Mono'`) for module / frame / port names, labels, values and keys; Sans (`'IBM Plex Sans'`) for
  words. Faces ship with the app (400 / 500 / 600); nothing is fetched at run time.
- Module, frame and port names stay uppercase; chrome copy (buttons, tabs, hints, placeholders, notices, dialogs) is
  sentence case. Panel content (port labels ≤ 5 characters, display tags such as `MISSING · kick.wav`) stays as is.
- The panel grammar does not change: 56 px HP, n × 144 px U, 32 px lanes, IN | controls | OUT, one jack per lane.
- Radii `radius-1…6` = 2 / 6 / 8 / 10 / 12 / 14 px; `shadow-1` modules, `shadow-2` floating, `shadow-3` dialogs and the
  drawer; `ring` = `0 0 0 3px` of `text` at 9 %.
- Audio-thread rules (CLAUDE.md) are untouched; `live.ts` readout writers stay allocation-free per frame.
- `pnpm check` passes before every commit; e2e (`pnpm e2e`) passes at every checkpoint.
- Each task ends with `pnpm screens` (Task 1) run and the six-skin captures compared with the boards; a checkpoint
  task also stops for the user to look at `pnpm dev`.

## Review Focus

- **Long text in the new Sans sizes** (a 60-character project name, `NOISY TECHNO DRUMS › CLAP` in a WIRES row, a long
  frame name): it ellipsises inside its box, never overlaps the next control. Pinned by `pnpm screens` cases
  (Task 1 adds a long-name project to the capture set) and by the Chrome test in Task 4.
- **The sidebar and the drawer together**: with META-SEQ's drawer open the floating sidebar ends 16 px above it, and
  F fits the patch into the canvas left of the sidebar. Pinned in Task 5 (e2e).
- **Frame tools without a mouse hover**: a frame selected from the keyboard or by a click shows its tools; a frame
  whose header the pointer leaves while it is selected keeps them. Pinned in Task 6 (Frame test).
- **Documents saved before revision 35**: a free frame whose child sits 16 px under the old 28 px header still has
  the child below the new 32 px header; a NOISE / OUT / A4 inside a STACK frame re-packs without overlap. Pinned in
  Task 6 and Task 2 (core tests).
- **Every skin at once**: a change made in DEFAULT that reads in another skin's `popover` below 4.5 : 1. Pinned by
  the contrast test in Task 1 (it runs on every skin, including the four fixed values).
