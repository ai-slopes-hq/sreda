# Plan 14 — META-SEQ Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or
> superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** One sequencer module, META-SEQ, replaces RHYTHM and STAGES: six polymetric lanes, eight patterns, an
editor docked under the canvas, DICE / ⚄ / MUTATE, old documents migrated.

**Architecture:** A Rust DSP (`engine/src/modules/metaseq.rs`) reads every lane step from hidden params (`fixed`)
and reports cursors, the playing pattern and its live (mutated) steps through a trace. TypeScript core owns the
param naming (`packages/core/src/metaseq.ts`), the generators and the migration; the UI adds an overview display and
a bottom drawer (`packages/ui/src/seq/`).

**Tech Stack:** Rust (engine, WASM), TypeScript core / protocol, SolidJS UI, Vitest, Playwright.

**Spec:** `docs/superpowers/specs/2026-10-07-canvas-ux-design.md` §7b (revision 33). Read it first.

1. A clock faster than a ×4 lane can subdivide (audio-rate CLK): outputs stay 0 / 1, no step is skipped forever —
   Task 1 `an_audio_rate_clock_stays_in_range`.
2. LEN lowered below a lane's cursor while playing: that lane wraps to step 1 on its next step, others continue —
   Task 1 `lowering_len_wraps_only_that_lane`.
3. The user edits a step while MUTATE is rewriting the same lane: the edit wins and is not overwritten by the next

5. The drawer open on a module that is deleted, undone away or replaced: the drawer closes, no stale id —
   Task 3 `the drawer closes when its module goes`.

## Param names (the contract every task uses)

Patterns `a`…`h` (index 0–7). Lanes, in this order everywhere (fixed layout, trace, UI rows):
`n` NOTE, `g` GATE, `t` TIE, `a` ACC, `v` VEL, `c` CHNC (index 0–5). Steps 1–16.

| id | kind | range / options | default |
|---|---|---|---|
| `{p}{l}{k}` e.g. `an1`, `hc16` | hidden | `n`: knob 0…24 step 1 (semitones, 12 = 0 V); `g` `t` `a`: option `·`/`●`; `v` `c`: knob 0…1 | `n` 12; `g` 1 on steps 1, 5, 9, 13 of pattern `a`, else 0; `t` `a` 0; `v` `c` 1 |
| `{p}{l}len` | hidden knob | 1…16 step 1 | 16 |
| `{p}{l}rate` | hidden option | `÷4 ÷3 ÷2 ×1 ×2 ×3 ×4` | 3 (×1) |
| `{p}{l}lock` | hidden option | `·` / `L` | 0 |
| `{p}nmode` | hidden option | `PLAYED` / `STEP` | 0 |
| `scale`, `root` | hidden | as STAGES' (`CHR`…`WHL`, def 2; 0…11 note) | |
| `edit` | hidden option | `A`…`H` (the pattern the drawer edits) | 0 |
| `pat` | knob | 0…7 step 1 (shown A…H) | 0 |
| `trns` | knob | −24…24 step 1, semitones | 0 |
| `mut` | knob | 0…1 | 0 |
| `dens` | knob | 0…1 | 0.5 |
| `gen` | option (2 HP list) | `303 MOTIF WALK TURING ARP PHRASE PEDAL EUCLID` | 0 |
| `dice` | action | | |

Spec param order: for each pattern, for each lane: its 16 steps, `len`, `rate`, `lock`; then `{p}nmode`; then
`scale`, `root`, `edit`, then the visible params. Inputs `clk`, `reset`, `dice`; outputs `cv` (pitch), `gate`, `acc`,
`vel` (mod), `eoc`. Size (6, 2); display `{ lanes: 4, kind: "metaseq" }`.

**Trace** (`TRACE_LEN` floats, display kind `metaseq` gets one): `[0]` playing pattern 0–7; `[1..7]` the six lane
cursors in lane order (−1 before the first step); `[7]` mutation generation (counts up on each lane mutation);
`[8..104]` the playing pattern's live steps, lane-major (lane × 16 + step), in param units (NOTE semitones, options
as indices). `state()` = the GATE cursor.

Behaviour (spec §7b) the tests pin:
- Per lane: a step event on each clock for ×1; ÷N on every Nth clock; ×N at the clock and N−1 times between, spaced by
  the last clock interval / N (as an input's ×N ratio). A lane wraps at its LEN (clamped to the current cursor:
  if the cursor ≥ LEN, the next step is 1).
- The GATE lane's step event decides the note. TIE on (whatever GATE says) and a note sounding → GATE stays high; a
  differing note glides 80 ms (as STAGES' slide). TIE on with nothing sounding → a hit. GATE on, TIE off → a hit if
  `rng < clamp(chnc · 2 · dens, 0, 1)`, else a rest. A hit: GATE rises (a one-sample gap if it was high, as RHYTHM),
  held half a GATE-lane step, or up to 4 GATE-lane steps when the TIE lane's next step is on; ACC 1 ms pulse if the
  ACC lane's step is on and the hit is not a tie; VEL holds the VEL lane's value.
- NOTE in PLAYED advances on each hit that sounds (not on a tie, a rest or a dropped hit) and ignores its RATE;
  in STEP it advances on its own step events. CV = `(snap(note + trns, scale, root) − 12) / 12`.
- PAT (`round(par)`, 0–7): read at the first clock; afterwards a different value switches only when the GATE lane
  wraps, every cursor restarting. EOC: 1 ms pulse on each GATE-lane wrap. RST rise: every cursor to none; the next
  clock plays step 1 of every lane.
- Live steps: the DSP keeps `live` and `seen` copies (`[[f32; 16]; 6]`, allocated in `new`) of the playing
  pattern; each block, a step whose `fixed` value differs from `seen` is copied into both (an edit wins). Task 1
  never changes `live` otherwise; Task 7 mutates it.
