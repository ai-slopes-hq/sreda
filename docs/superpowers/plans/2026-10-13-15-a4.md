# Plan 15 — the A4 module Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or
> superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** An `A4` module plays an Elektron Analog Four MKII over USB MIDI: notes on tracks T1–T4 from PITCH / GATE /
VEL cables, and MIDI clock with start/stop from CLK / RUN / RST. A project with it opens and plays with no A4
attached.

**Architecture:** The Rust DSP turns gates and clock into MIDI bytes with sample timing and pushes them into a new
engine outbox (`ctx.events`). The worklet copies them, stamped with absolute frames, into a SharedArrayBuffer ring.
On the renderer's main thread, `MidiPump` drains the ring and sends each event through Web MIDI at the time its
sample leaves the speakers (`getOutputTimestamp` + `send(bytes, time)`). `NoteLedger` releases notes when a node
goes, is muted or the audio stops, and `MidiDevices` tracks the port by name, with hot-plug.

**Tech Stack:** Rust (engine, WASM), TypeScript core / protocol, SolidJS UI, Web MIDI (Electron's Chromium),
Vitest, Playwright.

**Spec:** `docs/superpowers/specs/2026-10-13-a4-module-design.md` (revision 2). Read it first.

3. The main thread stalls 200 ms (a heavy redraw): the ring does not overflow at normal note rates, late events go
   out at once in order, note-off never before its note-on — Task 5 `late_events_keep_their_order`.

   Task 3 `unpatching_gate_releases_the_held_note`.
5. CLK stops (the frame clock switched off) and starts again 5 s later at a new tempo: no burst of stale ticks, the
   first new beat sends tick 0 only, and 24 per beat resume from the second beat — Task 7

## Contracts (every task uses these names)

**Spec `a4`** (Task 3 adds it; the clock DSP comes in Task 7):

| | |
|---|---|
| inputs, in order | `t1_pitch` P1 (pitch), `t1_gate` G1 (trigger, held), `t1_vel` V1 (mod), the same for `t2`…`t4` (P2 G2 V2 …), `clk` CLK (trigger), `run` RUN (trigger, held), `rst` RST (trigger) |
| knobs (visible, in order) | `t1_note`…`t4_note` NOTE 1–4: 0…127, step 1, default 48, `Unit::Note`; `offset` OFS: −50…50, step 1, default 0 |
| option | `clock` CLK: `OFF` / `ON`, default 0 |
| size / display | (8, 2) · `{ lanes: 2, kind: "device" }` |
| `state()` | bit mask of sounding tracks: bit 0 = T1 … bit 3 = T4 |

**Engine event** (Task 2): `ctx.events.push(offset: usize, bytes: [u8; 3])`; the engine sets the node. WASM
`events()` → `Uint32Array` view, 2 words per event: `node << 16 | offset`, `b0 | b1 << 8 | b2 << 16`.
`eventsDropped()` → number.

**Ring record** (Task 4): 4 × u32 `frameLo, frameHi, seq16 << 16 | node, midi`. Header Int32 `[head, tail, dropped,
_]`, then 4096 records. `midi` length: 1 byte if `b0 >= 0xF8`, else 3.

**MIDI status** (Task 5): `type MidiStatus = 'connected' | 'missing' | 'unavailable'`.

## Slice 2 — clock

### Task 7: MIDI clock, start, stop

**Files:**
- Modify: `engine/src/modules/a4.rs`, `engine/tests/alloc.rs` (CLOCK ON in the A4 there)

Behaviour (spec §2): with `clock` ON, each CLK rise is a beat. Tick 0 (`0xF8`) goes out on the rise. With the last
period P (samples between the two previous rises), ticks k = 1…23 go out at rise + round(k·P/24). An early rise
first sends the ticks still owed for the beat, at the same offset. A late beat stops at tick 23 and waits. No ticks
before the second rise. A gap > 2 s forgets P, so the next rise sends tick 0 only. RUN rise → `0xFA`, fall →
`0xFC`. RST rise → `0xFC` then `0xFA` at the same offset. CLOCK turned OFF while running → `0xFC`. Clock bytes have
no channel.

  `a_slower_beat_waits_at_23`; `nothing_before_the_second_rise`; `a_long_gap_resets_the_period`;
  `run_starts_and_stops`; `rst_is_stop_then_start`; `clock_off_while_running_stops`; `clock_off_sends_nothing`.
