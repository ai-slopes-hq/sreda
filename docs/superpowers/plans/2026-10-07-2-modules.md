# SREDA 2 · Plan 2 — The modules, one at a time

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** The other 22 first-build modules, each landing as a Rust file that appears in the app's picker and plays at
once, in an order where real patches come together early: SCOPE → *Pulse* → FILTER / MIX → *Acid* → *Drone* → the
rest.

**Architecture:** Plan 1's pipeline stays: a module is `engine/src/modules/<type>.rs` (`spec()` + DSP + unit tests),
registered in `registry.rs`, exported by `pnpm specs`, drawn by the generic `Panel`. This plan adds what some modules
need beyond that: a `state` and a `trace` readout per node, three displays (scope, contour, pads), the
`scale` / `curve` glyphs, action buttons, DICE and its generators (TS), a shared ADAA folder (Rust), and own-normal
ghost cables.

**Tech Stack:** as Plan 1 (Rust → WASM engine, TypeScript core, SolidJS UI, Vitest, cargo test, Playwright).

**Spec:** `docs/superpowers/specs/2026-10-07-canvas-ux-design.md` (revision 14): §3 signals and normals, §2 panels
and readouts, §4 knobs, options and glyphs, §7 the modules (table, STAGES contour, RHYTHM pads, rests and ties,
DICE, SCOPE sync). Each module's ports, params, ranges, defaults, `randomRange`, `modDepth`, normals and size are
the prototype's `SPECS.<type>` and `SIZES` (`docs/prototype/Main.dc.html`, from line 386) — port them; where §7 and
the prototype differ, §7 wins. The generators are the prototype's `euclid`, `genNotes`, `diceModule` (from line 859),
themselves ported from `../sreda/design/mockup/reference-js/seqgen.js`. The prototype's `Sim` is not a DSP
reference.

**This is Plan 2 of 3** (Plan 1 merged; Plan 3 — frames, WIRES, library, factory patches, the remaining gestures,
the 200-module benchmark — is written when this lands).

## Global Constraints

- Everything in Plan 1's Global Constraints holds (audio-thread rules, roles, stacking, attenuverters, ratios, knob
  modulation in knob space, glides, master, fades, panel grammar and quiet rules, colours, the 8 px grid).
- Every module works at any sample rate; times and frequencies are equal in seconds / Hz at 44 100 and 48 000.
- Trigger outputs are 1 ms pulses; gates last as long as they last.
- Bipolar mod outputs are ±1, unipolar 0…1, as §7 states per output.
- Normals the `Normal` type cannot express are done inside the DSP from `connected_in` / `connected_out` and declared
  `Internal` for display (A×B+C's `c2 ← out1 while out1 is unpatched`, ATT's cascade, LPG's cv).
- Nonlinear stages (FOLD, COMPLEX's timbre) use first-order ADAA with 2× oversampling (`engine/src/shaping.rs`).
- R (randomise) never touches hidden params (STAGES' and RHYTHM's per-step values); DICE writes them.
- Every new module: its spec fits its size (`layoutPanel(spec).fits`, already tested for every spec), and it gives
  the same output per block and per sample (the `blockwise_equals_per_sample` test below).

## Review Focus

1. An audio-rate square (2 kHz) into a clock input — RHYTHM CLK, STAGES ADV, SWITCH / SPREAD ADV, S&H TRIG — stays
   finite with outputs in their ranges (tests in Tasks 5, 6, 9, 10).
2. A sequencer edited while it runs — LEN lowered below the current step, DICE mid-pattern, ADDR beyond 1 — never
   indexes out of range; the step wraps (tests in Tasks 5 and 6).
3. Feedback through the new modules — MIX out into its own input at full level, DELAY feedback 0.95 into itself,
   FILTER res 1 — stays finite, and once the runaway is removed the output returns to silence within 0.5 s (master
   input clamp, Task 4).
4. Times and frequencies hold at 44.1 kHz: SLOPE rise / fall, LPG decay, FILTER cutoff, DELAY time, SCOPE time,
   UNCERTAINTY rate (tests in each owning task).
5. No allocation in `process` with every module type in one plan, including fades, crossfades and trigger inputs
   (`engine/tests/alloc.rs`, extended in Task 1 and again in Task 10).
