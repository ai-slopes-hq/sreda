# Plan 20 — CLOCK, a tempo module without a frame

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** a CLOCK module (document type `clk`, 3 × 1) that ticks at a modulatable BPM with a TAP button, so a tempo
needs no frame.

**Architecture:** the frame clock's beat generator in `engine/src/modules/clock.rs` is pulled out into a small
`Beat` struct that both the hidden `clock` node and the new `clk` module use; `clk` reads BPM from its knob
(`io.par`, modulation applied) instead of a hidden fixed value. TAP is an action param; the canvas turns taps into a
BPM through the existing `tapTempo`, kept per module, and writes the knob with one merged undo step.

**Tech Stack:** Rust (engine, WASM), TypeScript / SolidJS (UI), Vitest, cargo test.

**Spec:** `docs/superpowers/specs/2026-10-07-canvas-ux-design.md` §7c (revision 39); frame clocks §5.

## Global Constraints

- Nothing in `Dsp::process` may allocate, lock, await, do I/O, log or panic (`CLAUDE.md`, audio thread rules).
- CLOCK: inputs `clk` (trigger); knob `bpm` "BPM" 20–300, linear, default 120, random range 80–160; action `tap`
  "TAP"; output `clk` (trigger); size `(3, 1)`; label `CLOCK`; type id `clk`.
- One 1 ms pulse per beat (`((0.001 * sr).round() as u32).max(1)` samples), the first at once.
- While CLK in is connected its prepared input goes straight to the output and the own beat does not run.
- TAP: `tapTempo` rules (up to 4 taps within 2.5 s, at least 2; 20–300); a run of taps on one module is one undo step.
- After changing a spec in Rust: `pnpm specs`; after a module type is added: regenerate the plan fixtures with
  `UPDATE_FIXTURES=1 pnpm test packages/core/src/compile.test.ts`.
- `pnpm check` before every commit. Docs, code, commits and UI copy in English.

## Review Focus

1. **CLK in unplugged mid-run** — the own beat resumes with a beat at once, not after a stale phase. (Task 1 test
   `unplugging_clk_in_restarts_with_a_beat_at_once`.)
2. **BPM modulated past its range** (a mod signal driving `par` below 20 or above 300) — beats clamp to 20 / 300 BPM,
   never stall, never NaN. (Task 1 test `a_bpm_beyond_its_range_clamps`.)
3. **A single TAP** — no BPM change and no undo step. (Task 2 test.)
4. **TAP on two CLOCKs in turn** — each keeps its own tap history. (Task 2 test.)
5. **The frame clock after the refactor** — every existing `clock.rs` test and the engine's nested-frame tests still
   pass unchanged. (Task 1 Step 4 runs them.)
